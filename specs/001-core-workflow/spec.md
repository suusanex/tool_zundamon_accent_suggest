**Feature Branch**: `001-core-workflow`  
**Created**: 2026-01-27  
**Status**: Draft

## Clarifications

### Session 2026-01-27

- Q: 辞書登録モードで入力CSV/JSONにパース不能な行（壊れた行）が混ざっていた場合、処理方針はどれにしますか？ → A: 厳格（1件でもパースエラーがあれば登録処理は開始せず失敗で終了。エラー箇所を提示）
- Q: 辞書API登録で「同じ単語（surface）が既に辞書に存在する」場合、既定の挙動はどれにしますか？ → A: 既定=更新（同じsurfaceは置換する）。スキップに切替可能
- Q: 台本に個人情報/機密が含まれる可能性がある前提で、LLM（Azure OpenAI等）へ送信する際の方針はどれにしますか？ → A: 自動マスキング（検出した個人情報らしき箇所を置換してから送信）
- Q: 辞書案ファイル（出力/入力）の“正式採用（基準フォーマット）”はどれにしますか？ → A: CSVを基準（既定）。JSONも入出力でサポート
- Q: 台本が文字数制限（現状10,000文字）を超えた場合の既定挙動はどれにしますか？ → A: 失敗で終了（ユーザーに手動分割を促す）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 台本から辞書候補を抽出して編集 (Priority: P1)

広報担当者が新しいナレーション台本を準備する際、イントネーション調整が必要な単語を事前に洗い出し、適切な読みとアクセントを設定したい。

**Why this priority**: 辞書整備は音声合成品質の基盤であり、手作業での候補選定は最もコストが高い。このモードが機能しなければ、後続の辞書登録やリライトも価値を提供できない。

**Independent Test**: 台本テキストを入力し、辞書候補（単語、読み、アクセント核位置）が抽出され、CSV/JSONファイルとして出力されることで独立してテスト可能。ユーザーは出力ファイルを編集して次のステップに進める。

**Acceptance Scenarios**:

1. **Given** ユーザーが台本テキストを入力欄に貼り付けた、**When** 「辞書候補を抽出」ボタンをクリックした、**Then** 固有名詞・専門用語・特殊読みが必要な単語が候補として抽出され、読みとアクセント案が自動生成される
2. **Given** 辞書候補が抽出された、**When** ユーザーがファイル形式（CSV/JSON）を選択して保存した、**Then** 選択した形式でファイルが保存され、外部エディタで編集可能な状態になる
3. **Given** LLMによる抽出処理が失敗した、**When** エラーが発生した、**Then** エラー内容（APIエラー、トークン超過など）が明示され、部分的な結果があれば保存できる

---

### User Story 2 - 辞書候補をVOICEVOX APIに一括登録 (Priority: P2)

編集済みの辞書候補ファイルを受け取り、VOICEVOXのユーザー辞書APIに一括登録して、以降の音声合成で即座に利用可能にしたい。

**Why this priority**: P1で抽出・編集した辞書を実際に使えるようにする必須ステップ。ただし、辞書候補の抽出が先に機能しなければ意味がないため、P2とする。

**Independent Test**: 辞書候補ファイル（CSV/JSON）を入力し、VOICEVOX APIへの登録リクエストが実行され、成功/失敗レポートが表示されることで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** ユーザーが編集済み辞書候補ファイルを選択した、**When** 「API登録を実行」ボタンをクリックした、**Then** 各単語がVOICEVOX APIに順次登録され、進捗状況が表示される
2. **Given** 一部の単語登録が失敗した、**When** 登録処理が完了した、**Then** 成功件数・失敗件数が表示され、失敗した単語とエラー理由が記録される
3. **Given** API認証情報が正しくない、**When** 登録処理を開始した、**Then** 認証エラーが即座に検出され、登録は実行されず、設定ファイルの修正方法が提示される
4. **Given** 登録処理が中断された、**When** ユーザーが再実行した、**Then** 既に登録済みの単語はスキップされ、未登録分のみ処理される（冪等性の確保）

---

### User Story 3 - 台本を喋りやすく自動リライト (Priority: P3)

元の台本の意味を変えずに、音声合成で自然に読み上げられる表現にリライトして、読み上げ品質を向上させたい。

**Why this priority**: 辞書整備が完了していれば音声品質はある程度確保される。リライトは追加的な品質向上であり、必須ではないため、P3とする。

**Independent Test**: 台本テキストを入力し、リライト結果が表示され、コピー可能な状態になることで独立してテスト可能。辞書登録がなくても単独で動作する。

**Acceptance Scenarios**:

1. **Given** ユーザーが元の台本を入力欄に貼り付けた、**When** 「リライト実行」ボタンをクリックした、**Then** 意味を保持しつつ、読みやすさを向上させたリライト案が表示される
2. **Given** リライト結果が表示された、**When** ユーザーが「コピー」ボタンをクリックした、**Then** リライト結果がクリップボードにコピーされ、他のアプリケーションに即座に貼り付け可能になる
3. **Given** リライト処理が失敗した、**When** エラーが発生した、**Then** 元の台本が保持され、エラー内容が表示される

---

### Edge Cases

- **台本の文字数制限**: LLMのトークン制限を超える長大な台本（10,000文字以上）を入力した場合、エラーメッセージを表示し、文字数制限と分割方法をユーザーに提示する
- **辞書候補の重複**: 同じ単語が複数回抽出された場合、最初の出現を優先し、自動的に重複排除する。ユーザーは出力ファイルを編集して複数の読み/アクセント候補を追加できる
- **API接続失敗**: ネットワークエラーやAPIサービス停止時、指数バックオフ方式で最大3回までリトライする。すべて失敗した場合はエラーを表示し、ユーザーに再試行を促す
- **不正な入力/機密入力**: 台本入力に個人情報/機密が含まれる可能性があるため、LLM送信前に個人情報らしき表現（例: メール、電話番号、住所）を自動マスキングする。プロンプトインジェクション攻撃への対策として、システムプロンプトで明示的に「辞書候補抽出のみを行う」指示を含める
- **ファイル形式の不正**: 辞書登録モードで破損したCSV/JSONを入力した場合、パース時にエラーを検出し、具体的なエラー箇所（行番号、カラム名等）を表示する。1件でもパースエラーがあれば登録処理は開始しない
- **部分成功時の再実行**: 登録済みの単語（同一surface）を検出した場合の動作（スキップまたは更新）は appsettings.json の設定に従う。デフォルトは更新（置換）とし、再実行時に差分を収束させる

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは起動時にモード選択画面を表示し、ユーザーが「辞書候補抽出」「辞書API登録」「台本リライト」の3つから1つを選択できる MUST
- **FR-002**: 辞書候補抽出モードでは、台本テキストを入力として受け取り、LLM（Azure OpenAI等）を使用して固有名詞・専門用語・特殊読みが必要な単語を抽出する MUST
- **FR-003**: 抽出された各単語について、読み（ひらがな）とアクセント核位置（整数値）を自動生成する MUST
- **FR-004**: 辞書候補の出力形式は、CSV および JSON の両方をサポートし、ユーザーが選択可能である MUST
- **FR-005**: CSV形式は「単語,読み,アクセント核位置」のヘッダー付きで出力され、Excelで編集可能である MUST
- **FR-006**: JSON形式は `{"surface": "単語", "pronunciation": "読み", "accent_type": 数値}` の配列形式で出力され、プログラムで処理可能である MUST
- **FR-007**: 辞書API登録モードでは、CSV/JSONファイルを入力として受け取り、VOICEVOXユーザー辞書APIに順次登録する MUST
- **FR-008**: API登録時、認証情報（エンドポイントURL、APIキー等）は別ファイル（secrets.json等）から読み込む MUST
- **FR-009**: API登録の進捗状況（N件中M件完了）をリアルタイムで画面に表示する MUST
- **FR-010**: API登録完了後、成功件数・失敗件数・失敗した単語のリストをレポートとして表示する MUST
- **FR-011**: 台本リライトモードでは、元の台本テキストを入力として受け取り、LLMを使用して意味を保持しつつ読みやすさを向上させた代替表現を生成する MUST
- **FR-012**: リライト結果は読み取り専用のテキストボックスに表示され、ワンクリックでクリップボードにコピー可能である MUST
- **FR-013**: すべてのモードでウィザード形式のUIを提供し、各ステップで「次へ」「戻る」「キャンセル」ボタンを表示する MUST
- **FR-014**: すべてのLLM呼び出しとAPI呼び出しの結果（成功/失敗、トークン数、レスポンス時間）をログファイルに記録する MUST
- **FR-015**: ログファイルには台本の全文や個人情報を含む可能性のあるデータは記録せず、抽象化された情報（文字数、抽出件数等）のみを記録する MUST
- **FR-016**: LLM呼び出しまたはAPI呼び出しが失敗した場合、エラーの種類（認証エラー、タイムアウト、レート制限等）を明示的に表示する MUST
- **FR-017**: API登録時、既に登録済みの単語（同一surface）を検出した場合、スキップするか、更新（置換）するかを設定ファイルで制御可能である MUST
- **FR-017a**: 既定の挙動は更新（置換）とする MUST
- **FR-018**: すべての設定項目（LLMパラメータ、リトライ回数、タイムアウト値等）は appsettings.json に記載され、GUI上での変更はサポートしない MUST
- **FR-019**: システムは処理完了後、成否レポート画面を表示し、「終了」ボタンでアプリケーションを終了する MUST
- **FR-020**: 各モードの実行は1回完結型であり、連続して複数の処理を実行する機能は提供しない MUST
- **FR-021**: 台本が10,000文字を超える場合、エラーメッセージを表示し、文字数制限と分割方法をユーザーに提示する MUST
- **FR-022**: 辞書候補抽出で同じ単語が複数回抽出された場合、自動的に重複排除し、最初の出現を優先する MUST
- **FR-023**: LLM呼び出しまたはAPI呼び出しが失敗した場合、指数バックオフ方式で最大3回までリトライする MUST
- **FR-024**: プロンプトインジェクション攻撃への対策として、システムプロンプトで「辞書候補抽出のみを行う」という制約を明示的に指示する MUST
- **FR-025**: 辞書登録モードで破損したCSV/JSONを検出した場合、具体的なエラー箇所（行番号、カラム名等）を表示する MUST
- **FR-026**: 辞書登録モードの入力CSV/JSONに1件でもパースエラーがある場合、登録処理を開始せず失敗として終了する MUST
- **FR-027**: LLMへ台本を送信する前に、個人情報らしき表現（例: メール、電話番号、住所）を自動的にマスキングする MUST
- **FR-028**: 辞書案ファイルの基準フォーマットはCSVとし、ウィザード上の既定選択もCSVとする MUST

### Key Entities

- **台本 (Script)**: ユーザーが入力する音声合成用のテキスト。文字数、言語（日本語想定）、特殊文字の有無が属性。
- **辞書候補 (DictionaryCandidate)**: 抽出された単語と、その読み（pronunciation）、アクセント核位置（accent_type）のセット。単語の重複可能性、編集状態（未編集/編集済み）が属性。
- **辞書エントリ (DictionaryEntry)**: VOICEVOXユーザー辞書に登録される最終形。surface（単語）、pronunciation（読み）、accent_type（アクセント核位置）、priority（優先度）等のフィールドを持つ。VOICEVOX APIの仕様に準拠。
- **処理結果レポート (ExecutionReport)**: 各モードの実行結果。成功件数、失敗件数、失敗理由のリスト、実行時間、消費トークン数等の情報を含む。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーが辞書候補抽出を行う際、台本投入から辞書候補ファイル保存まで3分以内に完了する（500文字の台本を想定）
- **SC-002**: 辞書候補抽出の再現率が80%以上である（固有名詞・専門用語のうち、実際に調整が必要な単語の80%以上が候補に含まれる）
- **SC-003**: 辞書API登録モードで、100件の辞書候補を5分以内に登録完了する
- **SC-004**: API登録の成功率が95%以上である（正常なAPIエンドポイントと認証情報が提供されている場合）
- **SC-005**: 台本リライトモードで、元の台本の意味が保持されている（ユーザーによる主観評価で90%以上が「意味が変わっていない」と判断）
- **SC-006**: リライト後の台本が読み上げやすさで元の台本を上回る（ユーザーによる主観評価で80%以上が「改善された」と判断）
- **SC-007**: LLM呼び出しコストが1回の辞書候補抽出あたり平均100円以内に収まる（Azure OpenAI GPT-4想定、500文字台本）
- **SC-008**: システムの操作方法について、初回ユーザーがマニュアルなしで目的のモードを実行完了できる（成功率80%以上）
- **SC-009**: エラー発生時、ユーザーが原因を特定して自己解決できる（サポート問い合わせ率30%以下）
- **SC-010**: 台本に個人情報や機密情報が含まれていても、ログファイルには記録されない（監査で100%の非記録を確認）

## Non-Goals *(mandatory)*

- **音声ファイルの生成**: 本アプリは音声合成エンジンを直接呼び出さない。あくまで辞書整備と台本整形を支援するツールであり、実際の音声生成はVOICEVOXまたは他の音声合成ソフトで行う。
- **アクセント核位置の精密編集UI**: アクセントをGUI上で視覚的に調整する機能（波形表示、ピッチカーブ編集等）は提供しない。CSV/JSONファイルを外部エディタで編集することで対応する。
- **設定画面の提供**: appsettings.json や secrets.json をGUI上で編集する機能は提供しない。ユーザーは直接ファイルを編集する。
- **複数台本の一括処理**: 複数の台本ファイルをバッチ処理する機能は提供しない。1回の起動で1つの台本を処理する。
- **辞書のバージョン管理**: 登録済み辞書の履歴管理やロールバック機能は提供しない。VOICEVOX側の辞書管理機能に依存する。
- **他の音声合成エンジンへの対応**: VOICEVOXのユーザー辞書API以外（CeVIO AI、VOICEROID等）への対応は範囲外。
- **マルチユーザー対応**: 複数ユーザーが同一環境で辞書を共有・管理する機能は提供しない。シングルユーザー環境を想定。

## Assumptions *(mandatory)*

- VOICEVOXのユーザー辞書APIは、公式ドキュメントに記載された仕様（エンドポイント、リクエスト/レスポンス形式）に準拠している
- Azure OpenAIまたは互換性のあるLLMエンドポイントが利用可能であり、日本語の自然言語処理に対応している
- ユーザーはWindows 10以降の環境で本アプリを実行し、.NET 8 Runtimeがインストールされている
- ユーザーはappsettings.jsonとsecrets.jsonをテキストエディタで編集できる基本的なITリテラシーを持つ
- 台本は日本語で記述されており、UTF-8エンコーディングで処理可能である
- ネットワーク接続が安定しており、LLMエンドポイントおよびVOICEVOX APIに到達可能である
- APIキーやエンドポイントURLは、ユーザーが事前に取得・設定済みである（本アプリは提供しない）
- 辞書候補の「正解」は明確に定義できないため、再現率の評価にはドメイン知識を持つユーザーの手動レビューが必要である
- 台本の文字数制限は10,000文字とし、これを超える場合はユーザーが手動で分割する前提とする（自動分割は複雑性が高く、初期バージョンでは対応しない）
- リトライ回数は3回が妥当であり、これ以上は無駄なコスト増加とユーザー待機時間の増大につながると判断する
- プロンプトインジェクション攻撃の完全な防止は困難であるが、システムプロンプトでの制約により、実用上の安全性は確保できると判断する
- 辞書登録モードの入力ファイル（CSV/JSON）のパースエラーは、誤登録防止のため fail-fast（登録処理を開始せず失敗）とする
- 辞書API登録で同一surfaceが既に存在する場合、既定は更新（置換）とし、スキップへ切替可能とする
- 台本に個人情報が含まれる可能性があるため、LLM送信前に自動マスキングを行う（完全な検出/秘匿は保証しない）

## Constraints *(mandatory)*

- **UI形式**: ウィザード形式のデスクトップアプリケーション。各画面は「手順説明テキスト」「入力テキストボックス」「出力テキストボックス／リスト」「ナビゲーションボタン」を基本構成とする。
- **設定管理**: すべての設定は appsettings.json に集約する。GUI上での設定変更機能は提供しない。ユーザーはアプリを再起動することで設定を反映させる。
- **認証情報管理**: APIキー、エンドポイントURL等の機密情報は secrets.json（または環境変数）に分離し、バージョン管理システムにコミットしない。ファイル差し替えで環境切り替え可能とする。
- **外部依存**: Azure OpenAI（またはOpenAI互換API）とVOICEVOXユーザー辞書APIに依存する。オフライン動作はサポートしない。
- **プラットフォーム**: Windows専用デスクトップアプリ。macOS、Linuxはサポートしない。
- **データ形式決定軸**: CSV と JSON の両方をサポートする理由
  - CSV: 非エンジニアユーザー（広報担当等）がExcelで編集しやすい
  - JSON: プログラムによる自動処理や、VOICEVOX APIとの連携が容易
  - ユーザーのワークフローに応じて選択可能にすることで、利便性を最大化する
  - 基準フォーマットはCSV（既定）とし、JSONは互換フォーマットとして位置付ける

## Dependencies *(mandatory)*

- **Azure OpenAI Service**: 辞書候補抽出と台本リライトでLLMを使用。API仕様の変更やレート制限がアプリの動作に影響する。
- **VOICEVOX ユーザー辞書API**: 辞書登録モードで必須。APIの可用性、認証方式、データフォーマットの変更に依存する。
- **.NET 8 Runtime**: Windowsデスクトップアプリの実行環境。ユーザーが事前にインストールする必要がある。
- **ネットワーク接続**: すべてのモードで外部APIを呼び出すため、安定したインターネット接続が必須。

## Risks *(optional)*

- **LLMの出力品質の変動**: 同じプロンプトでも、LLMの内部更新や温度パラメータにより、辞書候補の抽出精度が変動する可能性がある。定期的な品質評価が必要。
- **APIコストの増大**: 大量の台本処理や、長文台本の分割処理により、LLM呼び出しコストが予想以上に増加するリスク。トークン消費量のモニタリングと上限設定が必要。
- **VOICEVOX APIの仕様変更**: VOICEVOXのバージョンアップやAPI仕様変更により、辞書登録が失敗する可能性がある。API互換性チェック機構や、バージョン固定の検討が必要。
- **プロンプトインジェクション攻撃**: 悪意のある台本入力により、LLMが意図しない動作をするリスク。入力サニタイズや、LLMへのシステムプロンプトでのガード指示が必要。
- **マスキングによる品質低下**: 自動マスキングにより文脈が欠落し、辞書候補抽出やリライト品質が低下するリスク。マスキングの範囲・置換表現の設計が必要。
- **個人情報の意図しない記録**: デバッグログや例外メッセージに台本の一部が含まれ、個人情報が記録されるリスク。ログ出力の厳格な管理が必要。
- **部分成功時のリカバリ複雑化**: 100件中50件が登録成功した状態で処理が中断した場合、再実行時に重複や競合が発生する可能性。冪等性の設計が不十分だと、手動でのリカバリが必要になる。

## Out of Scope *(optional)*

- **リアルタイム音声プレビュー**: 辞書登録やリライトの結果を即座に音声で確認する機能は提供しない。
- **辞書の共有・インポート/エクスポート**: 他のユーザーや環境との辞書データの共有機能は提供しない。
- **多言語対応**: 日本語以外の言語（英語、中国語等）の台本処理は対応しない。
- **音声合成パラメータの調整**: 話速、音高、抑揚等の音声合成パラメータの調整機能は提供しない。
- **高度な自然言語処理**: 文脈解析、感情分析、要約等の高度なNLP機能は提供しない。あくまで辞書整備とリライトに特化する。
